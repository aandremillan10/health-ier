## Direction and priorities

The incumbent interface fits a clinic staff tool: recognizable labels, explicit patient identity, separate disciplines, attributed entries, and conventional Windows controls. Keep it. Make interrupted work safer and clinical information easier to scan before adding visual effects or changing the component foundation.

1. **Confirmed patient-context defect — fix first.** Open the labeled memory-only demo as the default head doctor, open Lina/DEMO-0001, Medical chart, New medical entry, and enter `Synthetic unsaved text for DEMO-0001`. Open Ctrl+K, search Mateo, select DEMO-0003 and decline the discard confirmation. The coordinator's headless test showed Mateo/DEMO-0003 in the banner while the original unsaved text remained. `Workspace.select()` sets patient before guarded navigation resolves; the form save path reads its current patient prop. No save was attempted: this proves mismatched UI context and a misattribution risk, not an actual database write. Resolve the shared patient/screen/draft transition atomically after the dirty decision; cover decline, accept, request failure, and register shortcuts in regression tests.
2. **Complete the real integration gaps.** A named renderer → preload → main broker → NestJS path already exists. The live adapter nevertheless rejects patient-number search, refreshes patient-by-ID indirectly using a cached name, and lists documents only from a session cache. The handoff requires proper authorized patient lookup and persistent document history through all boundary layers, with final real Electron/API/PostgreSQL proof. Do not call a browser demo or backend health check complete integration.
3. **Make quick search as safe as the registry.** The registry shows birth dates for its two Lina records; the command palette shows only names and numbers. Add available authorized identity cues and missing-date wording without broadening role DTOs. Fix the doctor's instruction to choose an unavailable registration action and complete the palette's accessible selection semantics.
4. **Remove the empty-chart action ambiguity.** The existing age-calculation frontend case stopped because two visible `New medical entry` buttons matched its strict locator. Both currently open the same flow. Resolve redundant hierarchy or deliberately scope the test by a named region; retain its known/unknown-age assertions. The test did not establish an age-calculation defect.
5. **Improve clinical scanning and completion.** Reuse a measurement grid for linked vitals rather than a wrapped sentence of labels/units/numbers. Make Save draft/Cancel and patient identity easy to find in small/zoomed windows. Preserve long editable text and lifecycle meanings. Review the 700ms delayed post-save navigation for repeated tasks; immediate navigation with persistent honest feedback may be sufficient. Keep optional CS unchanged until the clinic clarifies it, as the approved specs require.

The separate [design assessment](clinic-ui-design-assessment.md) gives a provisional **27/40** across Nielsen's ten heuristics and documents the underlying observations. That score is indicative and does not override the confirmed patient-context defect. Strengths include duplicate-name registry guidance, author/read-only explanations and coherent neutral Windows controls. First-time staff primarily need clearer unknown fields and completion cues; frequent clinicians need immediate, safe quick search; keyboard/low-vision users need coherent focus/selection semantics and complete large-text verification.

## Palette and component decision

The source foundation matches DESIGN.md's neutral shadcn system: white cards, dark primary actions, neutral secondary surfaces, system/Segoe UI typography, and the exact approved success, warning and error text/background pairs. Assessment B calculated opaque token contrast ratios of **6.81:1 success**, **6.84:1 warning**, and **5.92:1 error**. These pass normal-text AA as token pairs; they do not substitute for rendered state/compositing checks.

Two local exceptions need contextual review rather than a palette replacement: `.draft-mark` uses `#7b4c10` and 11.2px text on paper; `.saved-check` uses a lighter green on a dark filled action. Their calculated contrasts are sufficient, but the draft label is small and both can be expressed consistently through semantic tokens. A dark success color must not simply replace the light button text. The original blue clinic logo is a retained asset, not an accidental second theme. Source labels are commonly 16px versus the approved 14px label scale; keep readability when reconciling that variation.

The [eight-library comparison](clinic-ui-libraries.md) recommends existing shadcn/CSS first, free beUI only for a demonstrable missing control, restrained Transitions.dev CSS ideas, and BoardUI table/layout inspiration. Do not install another theme, animation engine or paid source collection by default. The report distinguishes free/pro licenses, source ownership, accessibility evidence and unmeasured compatibility. Decorative charting, hover-only navigation, looping effects and animated clinical values are unsuitable for the approved tasks.

Assessment B's single mechanical scan found **two `overused-font` warnings**, both Arial declarations confined to print-paper fidelity. They are scope false positives under the existing print baseline. Detector silence elsewhere is not evidence of clinical safety or accessibility compliance. A password visibility control is 40×36px in source, below the repository's 40px minimum height; include it in target-size refinement.

## Motion gate

Invoked `find-animation-opportunities` as a filter for this staff interface. **No new motion opportunity needs implementation to solve the observed gaps.** Keep existing feedback only where it has a clear state purpose; the future implementer should invoke `animate` if a concrete accepted motion gap remains after the safety/layout work.

| Seam                             | Gate result                         | Reason                                                                                                                                                                             |
| -------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Button/clipboard feedback        | No new effect needed                | Active/swap states already exist; improve semantics before adding movement.                                                                                                        |
| Dialog/panel state               | No new effect needed from this pass | Native modal controls exist; unsaved-work ownership is the defect. A later occasional overlay may use existing 150–200ms opacity/transform tokens if it passes the frequency gate. |
| List additions and chart content | Reject decorative entrances         | Frequently read clinical information must appear immediately; existing table/entry reveal effects deserve restraint.                                                               |
| Group entrances                  | Reject                              | Routine work screens are not onboarding or marketing sequences.                                                                                                                    |
| Gesture seams                    | Cleared                             | No required drag/swipe workflow was identified.                                                                                                                                    |
| Rare delight                     | Cleared                             | No approved celebratory/onboarding gap calls for motion.                                                                                                                           |

Rejected candidates:

- Command palette open/close and Ctrl+K navigation: keyboard/frequency gate; immediate response is the useful behavior.
- Patient rows and clinical values: function gate; moving information makes identification and reading harder.
- Decorative shell/page entrances: purpose/frequency gate; no clinic task benefits.
- Long saved-state pause or animated counters: speed/function gate; repeated work needs truthful feedback without a forced delay.

The existing reduced-motion rule may remove movement entirely, consistent with DESIGN.md. Extend current duration/easing tokens rather than introducing parallel scales. Use pointer gating for any hover movement. New motions, if justified later, require an exact property/curve/duration recipe and a reduced-motion alternative before implementation.
