## Calculated contrast

Calculated in Python using WCAG relative luminance: normalize sRGB channels to 0–1; linearize at 0.04045 (`c/12.92`, otherwise `((c+0.055)/1.055)^2.4`); combine with weights 0.2126/0.7152/0.0722; contrast is `(lighter + 0.05)/(darker + 0.05)`. Achromatic OKLCH (`C=0`) was converted to equal linear-sRGB channels `L^3`. These are **opaque token-pair calculations**, not sampled rendered pixels, hover/disabled composite measurements, or a complete accessibility audit.

## Controls, focus, and ARIA findings

- **[P1] Patient identity can change after cancelling discard, while the previous patient's unsaved entry remains.** A subsequent parent headless probe opened DEMO-0001's new medical entry, entered “Synthetic unsaved text for DEMO-0001”, opened Ctrl+K, selected Mateo/DEMO-0003, and dismissed the discard confirm. The expected Lina heading assertion failed: the header showed Mateo/DEMO-0003 above the retained old text. **No save was attempted**, so persisted wrong-patient data is not claimed. This is a release-blocking patient-context error, not a decorative issue. Source independently shows `select` updates patient state before the guarded navigation can reject a screen change; EntryForm retains its existing local form state, and its save request reads the current `patient.id`, creating a concrete wrong-patient submission risk. Keep patient identity and editor state unchanged when discard is cancelled; verify both accepted and rejected patient-switch paths. [Selection/guard source](../../app/src/renderer/App.tsx#L422), [Entry save source](../../app/src/renderer/clinic/ClinicalForms.tsx#L91), [Parent headless screenshot](../verification/ui-review-2026-10-15/05-patient-guard-headless.png)
- **[P2] Password visibility target is below the repository minimum.** `.pw-toggle` is 40px wide × **36px high**. Its accessible name and pressed state exist, but its height falls below DESIGN.md's 40px standard-control minimum. This is a project-target mismatch; it does not automatically fail WCAG 2.2's 24px minimum. Enlarge the control without shrinking the password field. [CSS](../../app/src/renderer/clinic.css#L1284), [ARIA](../../app/src/renderer/App.tsx#L229)
- **[P2] Quick-search selection semantics need correction.** The input has `aria-controls` and `aria-activedescendant`, while the results are an ordinary `ul` containing buttons with `aria-selected`, rather than a coherent combobox/listbox/option model. `aria-selected` is not supported for the buttons' implicit role. Up/Down/Enter handlers exist, but source keyboard behavior does not establish that a screen reader announces the active result correctly. Adopt one consistent accessible interaction model and verify it with NVDA/keyboard. [Input](../../app/src/renderer/clinic/CommandPalette.tsx#L119), [Result markup](../../app/src/renderer/clinic/CommandPalette.tsx#L155)
- **[P2] Small preview draft marker merits enlargement.** Contrast passes, but 11.2px uppercase review text is below the staff-tool help/label size. Preserve the printed document's fidelity separately from the screen-only review indicator. [Marker](../../app/src/renderer/clinic.css#L1065)
