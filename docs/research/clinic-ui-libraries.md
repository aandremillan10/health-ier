# Clinic UI library suitability

Research date: **2026-10-15, Asia/Manila**. Scope: eight supplied first-party sites, their public documentation and linked source/license files. This is a recommendation, not a feature build or change to the approved design system. No packages, paid code, external agents, or browser interactions were installed or run.

## Recommendation

Keep **shadcn/ui New York as the component foundation**. Use existing controls and small CSS changes first. Of these references, **beUI's free components are the best candidate for a specific missing interaction**, **Transitions.dev is the best source of restrained CSS motion ideas**, and **BoardUI is the strongest table/layout reference**. None justifies adopting a second design system for this clinic.

The approved baseline remains system/Segoe UI, 16px body/input text, white surfaces, dark primary actions, readable labels, 40px minimum controls, visible focus, and semantic success `#166534`/`#f0fdf4`, warning `#92400e`/`#fffbeb`, error `#b91c1c`/`#fef2f2`. Routine and keyboard actions remain immediate; optional feedback lasts about 150–200ms with a reduced-motion alternative. Marketing effects, decorative charts, hidden gesture actions, and macOS/iOS imitation do not improve the approved clinic workflows. [Repository design requirements](../../DESIGN.md)

## Compatibility, ownership, and evidence

“shadcn-compatible registry” means source can be delivered by its CLI; it does not mean identical behavior, tokens, or zero integration work. Source copied into this app becomes code the frontend owner maintains. Vendor website dependencies include docs/demo tooling and are **not** the same as a selected component's dependency list. No renderer bundle was built or measured, so no numeric size or performance promise is made.

### Kobra

Kobra provides React source through `@kobra`; its documentation exposes individual registry metadata. The catalog includes Table, Alert, Empty, Skeleton, Input, and labelled form controls. Its stack uses Tailwind and Base UI; the inspected Input OTP imports `input-otp`, `motion/react`, and Tabler icons and handles `aria-invalid` and `useReducedMotion`. This is evidence for that component, not proof of every advertised WCAG claim. [Installation/catalog](https://kobra.systems/llms.txt), [Input OTP source](https://kobra.systems/components/input-otp), [Table](https://kobra.systems/components/table)

Technical reuse is plausible in React, but exact React 19/Tailwind 4 constraints were not independently established or compiled here. The house style intentionally uses 14px body text, two font weights, a translucent focus ring, and sounds; those defaults conflict with the approved clinic baseline. The same guide asks busy buttons to replace their label and remain enabled, which requires a separate duplicate-submission design. Copy only a genuinely needed, licensed component after reviewing its imports and behavior; do not install the global style or sound system. [Kobra design guide](https://kobra.systems/llms.txt)

The free pricing tier says **personal use only**. The paid Individual offer displayed $199 before local taxes; seats count people who read, copy, or edit source. Paid terms permit commercial end products but prohibit publishing source where it can be obtained without a license, including public repositories. The terms' general permission wording and free-tier wording do not clearly establish commercial free use; do not assume it. No public permissive source license was verified. **Recommendation: visual inspiration only**, especially if this project is published publicly. [Pricing](https://kobra.systems/pricing), [Terms](https://kobra.systems/terms)

### Arc UI

Arc explicitly supports **React 19 with TypeScript, Next.js or Vite**, including use without Tailwind. It delivers local source and CSS modules through `@uiarc` or manual copying. Its shared foundation/motion tokens and per-item imports add an integration layer: Motion, sometimes Lucide or Radix, and ES2023-or-newer library requirements. The free repository README provides these requirements and explains ownership. Do not copy the demo site's Next.js dependencies into Electron. [Official repository/install guide](https://github.com/kuratlielia/arc-library#install)

Search Field is a useful reference for an always-visible patient search: its source has an explicit label, named clear button, and restores input focus after clearing. It also removes input outlines, uses a 24px clear target, and includes blur/scale motion; those parts need adaptation to clinic focus/target requirements. `useReducedMotion` and a CSS reduced-motion guard are present. Number Field has much more scrubbing, rolling-digit and limit-motion machinery than clinical numeric entry needs. [Search Field source/metadata](https://github.com/kuratlielia/arc-library/blob/main/public/r/search-field.json), [Number Field source](https://github.com/kuratlielia/arc-library/blob/main/public/r/number-field.json)

Free repository code is **MIT**, with notice retention. Pro is a separate seat license; the site advertised $199 lifetime, but its license page explicitly marks the legal text **draft, pending review**. Arc's default Geist/Inter token foundation must not replace Segoe UI or the clinic colors. **Recommendation: borrow the search/state pattern, keep shadcn controls; consider one free component only if it demonstrably saves work after adaptation.** [MIT license](https://github.com/kuratlielia/arc-library/blob/main/LICENSE), [Pro/license limitations](https://uiarc.dev/license), [Site/pricing offer](https://uiarc.dev/)

### Kinetics

Kinetics is a gallery of CSS, React, and prompt snippets with spring-style parameter readouts. Its own site is built with Astro; consumers need not install Astro. Sample CSS often uses fixed-duration cubic-bezier curves rather than an actual spring runtime. Accordion-chevron feedback is the most transferable idea. Card Resize uses a clickable `div`; the hold-confirm sample uses pointer events without a keyboard counterpart. The snippets are motion demonstrations, not drop-in semantic controls. [Gallery and samples](https://kinetics.colorion.co/), [Repository structure](https://github.com/ckissi/kinetics)

The site's global CSS has a `prefers-reduced-motion` guard, but the inspected copied accordion/card/hold snippets do not carry that protection or complete accessibility behavior. Its gallery also contains 400–550ms motion and long looping effects, unsuitable for frequent clinic actions. The repository has no root LICENSE in the inspected file inventory and its README grants no explicit reuse license; freely viewable/copyable code is not evidence of commercial permission. **Recommendation: inspiration only; recreate a small generic CSS idea within existing controls rather than adopting snippets until permission is clear.** [Global reduced-motion CSS](https://github.com/ckissi/kinetics/blob/main/public/css/base.css), [Public repository files](https://github.com/ckissi/kinetics)

### beUI

beUI's public catalog explicitly targets **React 19 and Tailwind 4** and distributes editable source through the shadcn registry. Its stack adds Motion, Lucide, shared easing/utilities and, for some components, extra positioning/measurement hooks. Individual registry metadata must determine the actual imports; the docs site's Cloudflare, shader, Next.js, and analytics dependencies are not requirements for every component. [Official site](https://beui.dev/), [Source/install guide](https://github.com/starc007/ui-components)

The best concrete candidate is **Alert** for clear save/error/disconnected feedback, with persistent explanatory text. Source has reduced-motion handling, ARIA role support, and focus-return support when dismissing it. Tooltip source exposes keyboard descriptions/names and uses a reduced-motion surface; public tests exercise keyboard focus and axe checks. These are stronger evidence than a marketing accessibility claim, but were read, not executed here. Plain Tabs and Card are possible references; avoid Magnetic/Metallic buttons, Dynamic Island, blur-heavy modal navigation, swipe actions, and animated numeric values. [Alert source](https://github.com/starc007/ui-components/blob/main/components/motion/alert.tsx), [Tooltip tests](https://github.com/starc007/ui-components/blob/main/tests/tooltip.a11y.test.tsx), [Tooltip motion surface](https://github.com/starc007/ui-components/blob/main/components/motion/tooltip-surface.tsx)

Free source is **MIT**, requiring notice retention. Pro blocks/templates have separate paid access ($129 yearly or $179 lifetime shown for one person), and the Pro page is not evidence that paid files inherit MIT. Seats are permanently assigned after acceptance. No paid source or complete Pro redistribution terms were reviewed. **Recommendation: first compare existing shadcn Alert/Tooltip/Tabs; only adopt one free beUI component for a real gap, replacing its text sizes, colors, focus and motion defaults with clinic requirements.** [Free license](https://github.com/starc007/ui-components/blob/main/LICENSE), [Pro pricing/access](https://pro.beui.dev/)

### Transitions.dev

This supplies motion recipes, not a replacement control system. The modal recipe animates explicit opacity/transform properties and contains a reduced-motion media query; its CSS requires no animation package. Its React example injects a style tag and uses React state/timers. The example sets dialog ARIA roles but does not show full focus containment, restoration, Escape handling, or dialog naming. Use the CSS idea on the existing shadcn Dialog rather than replacing dialog behavior. Shorten the example's 250ms entrance to the approved 150–200ms range. [Modal recipe/source](https://transitions.dev/transitions/modal-open-close/)

Dropdown/panel reveal and skeleton-to-content fades are useful references. Reject confetti, gooey menus, smoky deletion, spinning counters, and page choreography for clinic work. The separate motion agent's score is not evidence of usability or a requirement that every action animate. [Catalog](https://transitions.dev/)

There is a material license mismatch: the pricing comparison labels core recipes MIT, while the repository LICENSE applies a **custom unlimited personal/commercial use license with a competing-library/kit redistribution restriction** to recipes/skills; only tooling is MIT. Free recipes need no plan under that license. Paid Pro is for personally paying individuals/freelancers; organization-paid or reimbursed use requires Business seats. Prices shown were $12/month Pro and $59/month Business for five seats; no purchase is needed for this recommendation. **Recommendation: selective free CSS inspiration, retain provenance and inspect the current license for any actual copy.** [Repository license](https://github.com/Jakubantalik/transitions.dev/blob/main/LICENSE), [Pricing comparison](https://transitions.dev/pro.html)

### BoardUI

BoardUI explicitly supports **React 19/Tailwind 4**, but is a separate design system based on **React Aria Components**, not shadcn's existing primitives. Its init writes global themes/type/styles and adds React Aria, Tailwind Merge and Remix icons. Source is copied locally; table blocks add TanStack Table, and other selections can add Motion/Recharts. Default Inter, blue actions, shadows and theme tokens need substantial clinic adaptation. [Installation](https://www.boardui.com/installation)

Its **Data Table** is the strongest task-oriented reference: sorting, filtering, search, pagination, labelled row actions and status chips. The inspected source uses React Aria table primitives and accessible labels, but its customer demo has a 1000px table minimum width and many composed imports; adapt the idea to the patient registry rather than copying it wholesale. **Sidebar** supplies a stable labelled navigation concept, although its floating panel, promotional card and unrelated destinations are unsuitable here. [Data Table docs](https://www.boardui.com/components/data-table), [Data Table source](https://github.com/BoardUI/boardui/blob/main/components/application/data-table/data-table.tsx), [Sidebar](https://www.boardui.com/components/sidebar)

React Aria is useful accessibility infrastructure, not proof of rendered contrast, zoom, focus or reduced motion. The inspected Notification source supplies status/alert roles but has Motion imports without local `useReducedMotion`; global handling was not established. [Notification source](https://github.com/BoardUI/boardui/blob/main/components/base/notification/notification.tsx)

Free repository source is **MIT**. Pro displayed €149 for one year of updates, €199 lifetime, or €349 for up to five developers; terms prohibit publishing Pro source in public repositories and count developers installing/editing it. Keep MIT free code distinct from those restrictions. **Recommendation: table and shell inspiration; no BoardUI init, Pro template purchase, or second control vocabulary.** [Free MIT license](https://github.com/BoardUI/boardui/blob/main/LICENSE), [License](https://www.boardui.com/license), [Current offers](https://www.boardui.com/)

### Evil Charts

Evil Charts supplies editable chart source via shadcn for **Recharts or Apache ECharts**, rather than general forms/navigation. Recharts components require Recharts; ECharts components require ECharts and their shared provider modules. The latter default to Canvas with an SVG option and do not pull Recharts. The repository's React 19/Tailwind 4 setup supports likely stack compatibility, but Electron integration was not built or measured. [Recharts installation](https://evilcharts.com/docs/recharts/installation), [ECharts installation](https://evilcharts.com/docs/echarts/installation), [Repository package manifest](https://github.com/legions-developer/evilcharts/blob/main/package.json)

A plain **Line Chart** with units, dates and readable legend could fit a later approved clinical trend requirement; a **Bar Chart** could fit an explicitly requested count comparison. Neither creates permission for a statistics dashboard. The line source uses `useReducedMotion` for entrance reveal; this does not establish keyboard/assistive access for every tooltip, Canvas view, dashed loop or loading animation. Any adopted chart needs an equivalent text/table interpretation and explicit checks. [Recharts line source](https://github.com/legions-developer/evilcharts/blob/main/src/registry/charts/recharts-line-chart.tsx), [ECharts line source](https://github.com/legions-developer/evilcharts/blob/main/src/registry/charts/echarts-line-chart.tsx)

Public source is **MIT**, with notice retention; the linked catalog showed no required paid tier. Dependencies and exact bundle impact depend on provider/imports. **Recommendation: defer; use existing chart tools only after a concrete approved data-reading task exists. Avoid decorative radar, radial, Sankey, financial or animated KPI blocks.** [License](https://github.com/legions-developer/evilcharts/blob/main/LICENSE), [Chart catalog](https://evilcharts.com/docs)

### Reverse UI

Reverse UI is a collection of animated components/demos, with React and Framer Motion examples and Tailwind or Emotion variants. Its pricing page offers 19 free components with commercial use and full source, and paid private-repository access: $39 one developer or $175 twenty developers displayed. This is vendor access/use wording, not a verified MIT or other public license. Exact redistribution rights and dependencies remain unverified. [Pricing/technology FAQ](https://reverseui.com/pricing)

**Timeline Progress** is a possible visual reference for real multi-step task feedback, although its demo only passes action strings and does not establish server-backed progress or accessible announcements. **Navigation Indicator** is a poor fit for essential clinic navigation: its description relies on hover tooltips and its component page marks Tailwind coming soon with an MUI variant, despite the general technology FAQ. Component-specific source must settle compatibility. [Timeline Progress](https://reverseui.com/components/timeline-progress), [Navigation Indicator](https://reverseui.com/components/navigation-indicator)

No convincing component-specific keyboard, screen-reader, or reduced-motion evidence was visible in the inspected public pages. Public source detail was incomplete, so bundle/React 19/Tailwind 4 support cannot be guaranteed. **Recommendation: no adoption; at most a static timeline idea.** Decorative orbs, shader fields, shiny actions and radial/dock navigation weaken predictable staff workflows. “Role-Based Access Control,” “Cloud Syncing,” “Signature,” and “X-Ray” component names are visual demos, not implementations of clinic authorization, mirroring, signing or medical functionality. [Collection](https://reverseui.com/), [Approved application boundaries](../specs/README.md)

## What adoption would require

For a separately authorized build, the frontend owner should identify one missing interaction, compare it with the existing shadcn component, inspect the exact source/registry dependencies and license, and keep all assets/runtime work local to the Electron renderer. Preserve the approved typography, controls, colors and API boundaries. Verify actual keyboard/focus behavior, Windows reduced motion, save/error semantics, 200% text zoom, narrow windows and rendered contrast. Clinical values and patient identity should appear immediately, never through rolling numbers or text reveals. A polished screenshot, library accessibility claim, or upstream test suite is not evidence that the integrated clinic flow passes these checks.

Research limitations: some documentation URLs failed HTTP/connector retrieval; linked public repositories supplied source where available. Paid source and runtime behavior were not inspected. Prices are observations on the research date, not purchase quotations. No compiled bundle benchmark or interactive accessibility audit was performed.
