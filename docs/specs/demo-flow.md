# Approved clinic staff demo specification

Status: **approved clinic-demo-v1 acceptance criteria, 2026-10-14, Asia/Manila**. See [approval record](approval.md). Target ready date: October 15, 2026; presentation October 16 morning, Asia/Manila. Final spec approval enables issue publication; feature code waits for a separate explicit build instruction.

## Outcome and ownership

Staff find/register a synthetic patient, record vitals, finalize a medical consultation, prepare a prescription and medical certificate, and print fixed templates. A synthetic dental/lab example proves permissions and head oversight. The complete flow works with internet disconnected while LAN/server remain available. User owns Backend; teammate owns Frontend; both agree [API contract](api-contract.md) and shared end-to-end evidence.

## Backend acceptance criteria

| Flow             | Result                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Named login      | Eight named synthetic seeded accounts, one doctor head, real local password login through a controlled setup command; no account-admin UI. WAN outage does not prevent local login. No public role self-registration or hardcoded identity bypass.                                                                                                                         |
| Find/register    | Authorized clerk/attendant can find/create/update shared demographics using agreed fields. Validate names/categories/identifiers and report invalid input. A UUID is identity storage, not duplicate-person detection.                                                                                                                                                     |
| Vitals           | Attendant authors timestamped measured values/units directly for selected patient. Own draft/version/finalize/correction checks apply; authorized care reader sees them without exposing provider notes to attendant/clerk.                                                                                                                                                |
| Consultation     | Medical chart entry is the consultation; doctor saves own dated draft, explicitly selects optional finalized same-patient vitals, finalizes, and appends own corrections preserving original/reference. No separate encounter container. Version checks reject stale writes.                                                                                               |
| Fixed documents  | Original doctor author issues from own finalized medical consultation using trusted issuer identity. Colleague/head read-only cannot issue as another author. Editable purpose/document wording never updates registry/consultation implicitly. Use supplied flattened form bodies and latest unified header, handwritten signature area, no stored signatures or builder. |
| Print            | Narrow preload/main-process operation validates sender, authorized document, printer/options. Local assets allow printing during WAN outage. Return actual submission/failure; retry refers to the same document rather than silently issuing another.                                                                                                                     |
| Dental/lab proof | Seed isolated dental/lab records for role/author proof. Dentists share dental reads; medtechs share lab reads. Own-author mutations follow common rules only where needed for proof. Doctor/dentist without head cannot retrieve laboratory content; medtech never receives medical/dental notes. No order/referral sharing or full lab workflow.                          |
| Head proof       | Head reads across disciplines and authors own medical work; direct attempts to change others' drafts/finalized entries/corrections fail.                                                                                                                                                                                                                                   |
| Connectivity     | WAN failure preserves shared read/write/print. LAN/server failure is clearly reported; no false durable-save success or workstation sync promise.                                                                                                                                                                                                                          |

## Frontend acceptance criteria

| Flow           | Result                                                                                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sign in        | Named staff/role identity; useful sign-in error; relevant staff tasks; no unrelated dashboard metrics.                                                                                                                                                                     |
| Registry       | Patient search/registration with agreed fields, clear empty/validation states, visible selected patient before entering care data.                                                                                                                                         |
| Vitals         | Labels/units, timestamp, selected patient, and saved/unsaved status; doctor selects relevant finalized timestamped vitals or none. No provider-note navigation for attendant.                                                                                              |
| Chart          | Clear medical chart and permitted history; separate save/finalize/correction actions; read-only explanation for other authors/head oversight.                                                                                                                              |
| Documents      | Original doctor author selects prescription/certificate from own finalized consultation, edits permitted wording/purpose, previews fixed form, chooses/confirms printing. Others with chart read access may only view/reprint existing document. No template-authoring UI. |
| Print result   | `Sent to printer` on accepted submission, actionable failure and explicit retry. Never imply paper output merely from submission.                                                                                                                                          |
| Full states    | Loading, empty, validation/error, denied, disconnected, disabled, unsaved, conflict, and success states. Meaningful labels, accessible help, visible focus, keyboard operation, reduced motion.                                                                            |
| Session switch | Clear prior patient/chart/documents/cache; head/doctor content cannot remain visible after switching to clerk/attendant/other discipline.                                                                                                                                  |

## Shared end-to-end evidence

Use synthetic patient and named role accounts. Exercise registration → vitals → medical draft → finalization → original-author correction → prescription/certificate preview → selected printer. Re-read from another client/restart to prove server persistence. Compare document content/header against approved photos; test physical paper when the printer is available.

Show colleague shared read, denied cross-author/cross-discipline direct calls, head read-only boundaries, minimum lab response, protected document access, stale mutation conflict, and logout/cache clearing. Disconnect WAN with LAN/server intact and repeat local login/read/save/print. Record actual command results, synthetic fixture IDs, flow evidence, and gaps. Headless/API checks are authorized. Interactive Chrome/device QA requires shared-resource confirmation and exact-session identification under AGENTS; coordinate physical printing in the assigned office/demo setup.

User supplied flattened forms and unified JPEG/transparent header in `docs/headers/`; source reviewer inspected all four. Prefer high-resolution JPEG for white-paper output; PNG currently has only 19% of its width. Rebuild native text/rules from form references rather than using photographic shading as page background. Assets no longer block template input readiness; implementation still waits for a separate build instruction. Astra handoff is preauthorized only for print templates. Verify actual paper/margins and `CS` with clinic/printer during implementation; preserve optional `CS` text until clarified.
