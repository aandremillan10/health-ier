Clinical fields/units are approved for this demo. Numeric validation checks finite values, types, declared units, and physically defined bounds where applicable (for example, a percentage from 0 to 100); it must not reject abnormal patient measurements using invented normal-range rules. Unknown/unmeasured values remain null. Use server ISO timestamps and date-only consultation/issue dates with Asia/Manila presentation. UUIDs may identify stored entities; optional employee ID does not imply eligibility or a unique person.

Approved native session transport: packaged renderer is `file://`, so use a server-managed opaque session token held only in Electron main-process memory. Login sends credentials through narrow typed sender-validated IPC; main calls the configured clinic server with `net.fetch` and attaches `Authorization: Bearer <session>` on named operations. Renderer receives principal/permitted results only, never token, raw IPC, arbitrary URLs, or a general-purpose request proxy. Credentials/tokens are not persisted or logged. Main validates sender/operation/payload/server identity; Nest validates session and permissions on every request. Logout invalidates server session, clears main token and renderer caches/previews; restart requires login. Production clinic traffic requires TLS. Explicit synthetic local development/demo HTTP is temporary and carries no real clinic data; it is not production transport approval.

Errors use a discriminated `code`, safe `message`, optional `fieldErrors`, and authorized conflict revision details. Approved statuses: 400 validation; 401 missing/expired credentials; 403 denied known operation without sensitive resource identity; 404 absent or concealed inaccessible patient/entry/document; 409 stale revision/lifecycle conflict; 503 unavailable dependency. No error includes restricted content. Search/list responses omit inaccessible records, and every nested DTO is scoped before transmission. Protected documents have no unauthenticated static path.

Exact envelope/ack examples and bootstrap/retry tests are in the amendment; implemented routes receive working usage examples/end-to-end checks.
