# Implemented synthetic EDGE API

The NestJS server persists approved `clinic-demo-v1.1` records in PostgreSQL. Staff routes run only in EDGE mode. CLOUD rejects staff login/read/mutation; dedicated mirror ingestion is implemented separately. HTTP below is temporary loopback synthetic development transport. Clinic production traffic requires TLS.

Run the complete authenticated Windows examples with the live EDGE server running:

```powershell
cd server
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-live.ps1
node dist/live-db-checks.js
# After restarting the server:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-persistence.ps1
```

`verify-live.ps1` contains executable `curl.exe` requests for every route in this table, obtains session tokens privately, selects returned IDs/revisions, asserts response status/content, and deletes temporary request files. No passwords/tokens are printed. It writes only synthetic IDs to ignored `.private/api-evidence.json`. Repeated runs create new synthetic patients and documents; they do not reset existing evidence.

Dates are date-only where stated, timestamps ISO, unknown values explicit null. Sex accepts `female`, `male`, `other`, `unknown`; category accepts `employee`, `dependent`, `other`, `unknown`, or null. Category/reference remain informational with no eligibility/unique-person enforcement.

All bodies reject unknown fields, including caller author/head/issuer/status authority. Errors are `{code,message,fieldErrors?,currentRevision?}` with 400 validation, 401 authentication, 403 known denied operation, concealed 404 inaccessible records, 409 revision/lifecycle, and 503 dependency failure. Conflict revision appears only after authorized access. Bodies expose no credentials or unauthorized clinical context.

Each successful registry/vitals/entry/finalization/correction/issuance transaction also writes the exact allowed immutable outbox version. A correction checks the current original revision, appends its own revision-1 record, and advances only the original revision/timestamp; finalized clinical fields stay unchanged. Documents preserve finalized original source content and source revision at issuance. They do not silently apply or edit correction history or demographics. Read/reprint cannot issue another ID. Cloud delivery never gates local save.

Issued snapshot fields: patient identity/age/CS; session-derived issuer display/license/PTR; finalized original consultation ID/revision/date/reason/findings/impression/plan; document body/purpose/remarks/restriction/follow-up. Fixed print presentation and physical printer proof belong to the privileged Electron/template work; API issuance alone does not prove paper output.
